CASE 1 // KAFKA & CONCORRÊNCIA

Resolução de Concorrência e Duplicidade no Kafka

Cenário: Migração de COBOL/IBM para Java + MongoDB na Casas Bahia. Triggers no IBM postavam atualizações simultâneas gerando concorrência (race conditions) e duplicidade no Mongo.

Solução: Pipeline com tópico interno agrupando por Entity Key e reordenando eventos sequencialmente antes da escrita final.

"Database triggers sent many updates to Kafka at once causing race conditions. I fixed this by partitioning by entity key and reordering events before saving."
